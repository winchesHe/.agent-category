# Observation｜上线观察与反馈

## 标准动作

用户点名上线观察、指标、错误或反馈时立即执行。没有 Release 回执、观察计划或既有驾驶舱时，从真实部署和数据源发现当前观察对象；只有多个 release/环境都可能是目标且无法唯一消解时中断。

## JIT 执行参数

在读取数据时解析实际 release SHA、环境/放量范围、当前窗口、指标口径、GA/白名单分母和数据可用性。版本或窗口变化时不与旧样本混算。

## 数据源

- 产品行为、漏斗、功能使用：`$posthog-skills`。
- 业务数仓口径：`$redshift`。
- 日志、APM、metrics、monitor：`$datadog`。
- 前后端错误与版本归因：`$sentry`。
- 客户/社区反馈：适用时使用 `$moe-feedback-collector`。

只加载与当前指标/问题有关的 owner Skill。数据不可得、权限缺失、样本不足或窗口未到时写 `不可计算`/Limitations；不用另一来源冒充。

## 执行

1. 锁定当前 release、环境、范围、窗口、指标和护栏；缺历史计划时从本轮建立。
2. 每轮 identity 为 `{requirement, release SHA, window}`；重复执行先回读后 skip/update。
3. 回读时间范围、过滤条件、基线和当前值，区分曝光、实际使用和业务结果。
4. 排除测试、内部账号和自动化流量；反馈按唯一 Business 去重并保留消息数。
5. 汇总错误、性能、反馈和业务结果。普通修复进入 Development；需要用户未表达的暂停、回滚或权限策略时才中断。
6. 适用时建立 T+2/T+7/T+30（低频可 T+60）后续调度；调度失败不撤销本轮观察结果。

## 结果与回读

- 数据来源、口径、时间窗、限制和 release identity 可追溯。
- 效果卡包含分母、曝光/使用/结果、错误/性能、反馈分类、结论和下一动作。
- 不可得数据明确写“不可计算”，不写成无异常。
- Query 模式只读；Explicit Observation 可以写调度和结果记录并回读。
