# 跨会话积累与增量维护

同一主题涉及多次任务、已有手册或规则、版本环境差异，或需要合并与更新经验时读取。共同检索和核证规则沿用主文件；这里展开如何将事件证据关联到已有结论并维护当前有效内容。

## 围绕使用主题建立对照

先定位已有权威资料，列出当前目标需要的主题与待核对结论，再关联相关独立事件。按使用问题整理正文，不按会话顺序堆叠复盘。

工作对照可包含：已有条目及位置、要支持的使用问题、适用条件、原证据、新事件、差异或冲突、建议处理。只记录实际需要的信息，不为此新建数据库或强制状态文件。

同一事件的主会话、fork、subagent 记录和后续总结形成一条来源关系，不能增加验证次数。一个任务中的多个独立操作也不必强行并为一个事件。根据目标、时间、对象、版本和结果判断；无法确认是否同一事件时保留疑点，避免虚增证据。

已有总结用于定位原始证据。若它比原记录更笼统，回到实际动作和结果判断，不让总结语气的确定程度提高证据强度。

## 对齐条件后处理冲突

先核对版本、环境、接口或工具语义、资源状态、目标范围和验证方式。两个结论在不同条件下成立时，可以分别保留，并写清选择分支的依据。

条件相同而结论相反时，比较各自依据是否直接支持对应结论；时间较新只能提供追查线索，不能自动胜出。明确要求、实测结果和实现描述各有证明对象，不建立简单的全局“证据排行榜”。

处理旧内容前区分其性质：

- **描述实现现状**：例如入口、参数、配置位置。实际实现改变且已核对相应版本时，修订描述；只有静态核对时不宣称新步骤已实测。
- **表达仍有效的要求**：有独立约定、契约或其他依据支持时，当前代码不满足要求可能是实现回归。保留要求并记录冲突，不为迎合当前代码而改掉正确要求。
- **存在验证缺口**：原记录或环境不可访问，不等于结论已经错误。保留必要的历史范围并说明当前缺口；只有矛盾或失效依据成立时，才进一步降级、修订或废弃。

未能解释的冲突列出两边依据、已对齐条件和还需什么证据。不要自行裁定缺少依据的长期要求，也不要为了完成更新而选择更方便的一边。

## 选择最小有效变更

| 判断 | 处理 |
|---|---|
| 现有内容准确且覆盖当前目标 | 无变化；可以报告已核验，不为更新时间改正文 |
| 新事件重复支持现有结论 | 按需要补来源或覆盖条件，不重复造条目 |
| 入口、参数、引用等局部变化，流程仍成立 | 定位相关段落修订，并核对上下游步骤 |
| 原适用范围过宽或存在新分支 | 缩小范围或补充条件，保留仍成立的部分 |
| 多条内容回答同一使用问题且重叠 | 合并独有细节到权威位置，检查原引用 |
| 已有证据证明旧建议不再适用 | 修订、替换或废弃，并说明有效替代或缺口 |
| 只有不确定的新解释 | 保留候选，不覆盖已有有依据的做法 |

同一服务、相同代码路径或相近关键词，不足以说明两个主题应合并。考虑下次按症状查找时，独立条目是否更容易区分问题；合并会隐藏不同前提、诊断分支或受众时，保留分别组织并建立引用。

发现单篇文档包含多个独立问题时，可按实际检索需要重组；长度本身不是拆分理由。结构变化必须直接改善使用，不顺带整理无关内容。

## 局部修订与有效信息保留

先确认需要改变的结论，再从原文和本次要求中提取保留清单：仍需支持的版本或环境分支、前提、参数、顺序、例外、判据、来源，以及已知被引用的标题或锚点。清单只覆盖本次改动涉及的内容，可保存在简短工作记录中，不要求另建文档。

修改后逐项定位其在最终正文中的承载位置；“修改说明提到了”不等于正文仍可使用。缺项时补回有效内容，确需删除时核对失效依据及本次范围。兼容分支中的旧命令仍有效时完整保留，不能仅在说明中写“兼容旧版”而省略操作路径。

合并时检查被并入材料的独有信息是否已进入正文或可用引用，不能只凭主题重叠认定已覆盖。若移动、删除或废弃条目，先查看哪些文档实质依赖它，并处理本次授权范围内的引用；范围外的依赖列为待处理事项。

对已知引用，核对最终路径和实际标题生成的锚点或显式锚点。标题改名时保留兼容锚点，或更新授权范围内的引用方；不能修改引用方时优先保留原目标。未完成目标核对，不宣称旧链接仍可用。写入文件后回读实际文件；仅交付替换正文时检查该正文，不宣称已更新依赖文件。

旧操作只有在解释当前差异、兼容环境或提供必要证据时保留；正文应能直接体现当前有效做法，不把每轮修订追加成历史流水。

更新后的状态仍可分层表达：当前已核验的步骤、历史验证但当前待核验的部分、待解决冲突。不要将验证缺口藏进脚注后在正文无条件推荐，也不要因缺少当前证据而抹去历史事实。

## 权威承载与重新核验

每项知识选择一个最窄且负责该问题的权威位置。手册中的完整操作不需要复制进全局规则；其他位置用可定位引用连接，需要加载时写清条件。

实际更新以当前授权为准。只有总结需求时交付整理结果和具体更新建议；已授权更新相关手册或 Skill 时，完成相应修改并回读。经验内容、发现方式和执行权限继续分别处理。

重新核验条件写成能观察到的变化，例如相关接口或参数调整、工具升级、消息消费语义改变、环境迁移、约定更新。必要时保留实际核验日期和范围；不能只因材料较旧就宣布失效，也不为维持日期新鲜而制造无意义编辑。

## 验收增量维护结果

按更新后的使用路径核对：

1. 关键结论是否对应独立证据，转述是否被正确关联。
2. 新旧结论是否在相同条件下比较，不同条件是否有明确分支。
3. 仍有效的必要信息是否保留，步骤输入输出是否仍衔接。
4. 合并后的标题和索引是否仍能按原症状找到内容。
5. 引用是否可定位，权威位置是否唯一，旧引用是否得到处理或明确标注。
6. 正文的验证语气是否符合实际覆盖，未知和冲突是否有具体缺口。

无需修改时直接给出无变化结论及必要依据。提炼出新信息不等于必须新增条目，完成维护也不等于所有历史结论都已经重新实测。
