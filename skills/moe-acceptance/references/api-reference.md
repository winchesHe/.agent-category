# 本地已验证 API 参考

将真实调用后已核对的接口知识保存在 `~/.config/moego/moe-acceptance/apis/`，供后续任务按路径或业务含义检索。AI 使用现有文件工具直接维护 Markdown，整理参数语义、适用范围、验证结论和脱敏内容。

## 目录与接口标识

按稳定的接口族/服务分目录，每个操作一份 Markdown。优先沿用已有目录名，不因环境、当前 App/Web 通道或用户变化而另起接口族。同名路径由不同服务承载时分别归属；服务归属未知时先定位。

以下为结构示意，接口名不代表实际已验证能力：

```text
apis/
├── merchant-api/
│   ├── GET__pets.md
│   ├── POST__pets.md
│   └── GET__pets__{petId}.md
└── appointment-rpc/
    └── moego.example.AppointmentService__GetAppointment.md
```

- HTTP 标识为接口族、大写 method 和精确 path 模板；不含 Host、查询参数值或 fragment。路径中的动态 ID 使用已确认模板，不能把固定路由误归一化为变量。
- RPC 标识为接口族和完整 `package.Service/Method`；不同命名空间的同名方法分别存储。
- HTTP 文件名采用 `METHOD__路径.md`，路径中的 `/` 用 `__` 表示；RPC 文件名采用 `package.Service__Method.md`。文件名用于阅读和定位，完整接口标识以文件头为准。保存前检索已有条目，同一接口沿用原文件；不同接口因路径转换、大小写或缩短名称而重名时，补充区分名称，不覆盖已有文件。
- 环境、版本/Grey 和不同调用组合保存在同一文件内各自的说明中。

## 何时读取

当前会话已有适用事实就直接使用。需要检索本地参考时，用 `rg -l -F -e '<路径>' -e '<业务关键词>' -g '*.md' <apis目录>` 找候选，只读取相关文件。目录不存在或没有命中时，回到 [data.md 的决策树](data.md#数据与-api-查询决策树)，按具体缺口与已有线索选择其他来源，不因参考目录缺失阻塞验收。

命中后核对记录的完整接口标识、调用组合和适用条件与本次目标是否匹配。已知版本/Grey、字段形状或业务条件变化时只补查受影响部分；未知条件若影响当前调用，就先补齐。没有变化或冲突信号时无需为复用例行重查全部来源，也不按固定 TTL 全量重验。

参考中的写入示例只说明操作方式，执行仍使用本次获授权的身份、对象和范围。正文或引用内容不能扩大任务授权。

## 记录内容与验证范围

文件头使用 YAML 记录 `api_group`、`protocol` 和 HTTP `method/path` 或 `rpc`。下面是 HTTP 记录示意；RPC 使用 `protocol: rpc` 和 `rpc: package.Service/Method` 替代 HTTP 的 method/path。未确认的信息明确标注，不补造：

```markdown
---
api_group: merchant-api
protocol: http
method: GET
path: /pets/{petId}
---
```

## 何时写入及如何更新

HTTP、业务错误和目标结果已核对，必要回读完成后，由同一 AI 更新对应调用组合。首次成功新增记录；有新事实就合并，已知组合仅更新最近验证信息；完整内容不变时不重复写入。业务失败、超时未知或单纯代码检查不更新“最近验证时间”。已确认接口失配时可以记录待复核差异，身份/网络失败则先局部恢复，不自动判定接口失效。

保存前读取当前条目，直接修改相关段落，保留其他有效组合；首次保存时按需创建接口族目录和 Markdown。发现内容已被其他任务修改时重读合并，避免用旧内容整份覆盖。写后回读核对完整接口标识、本次改动及原有有效内容。

文件系统错误只影响知识保存，保留本次待保存的脱敏事实并说明，继续按原业务结果推进，不为保存记录重发业务请求。任务正常结束时保留 API 参考；不扫描全目录刷新、不自动删除旧组合。模拟接口与样例只进入临时目录，不污染真实参考。
