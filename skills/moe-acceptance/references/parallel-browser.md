# 双浏览器上下文验收

## 适用边界

默认先用一个浏览器上下文。只有账号/环境确实不同、数据互不干扰，且并发能节省时间时，才建立第二个独立 session；最多两个浏览器上下文。每个 session 内 case 串行。

不要为了形式上的并发先复制 worktree、准备两份数据或执行两次账号解析。确认第二个上下文能减少总耗时后再建立它。

## Session 之间的隔离

每个 session 至少保留：

- 账号引用和环境；
- 当前环境摘要与各自的 Whistle 目标/规则引用；
- browser/tab/session 标识；
- 已准备的数据引用；
- 当前 case 和观察。

这些是 AI 的轻量工作记忆，不要求单独的持久化 registry。不要只用“浏览器 1/2”作为身份标识。

## 共享 worktree 的规则

两个 session 可以同时观察，但共享 worktree 的代码编辑和服务重启必须串行：

1. 一个 session 提出最小代码差异并完成修改；
2. 等待 HMR 或受影响服务恢复；
3. 两个 session 再判断各自 case 是否受影响。

真正需要并行编辑时，使用独立 worktree。仅仅为了观察两个账号，不需要复制 worktree。

## 完成与失败

一个 session 完成不代表另一个完成。某个 session 失败时，只恢复相关的账号、数据、浏览器、服务或代码上下文，不自动重置另一个 session。默认不清理数据，除非污染、配额或用户要求改变这个决定。
