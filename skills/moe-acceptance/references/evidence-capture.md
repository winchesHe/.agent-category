# 现场证据采集

当前 Claim 的采集规格、来源或隐私边界不明时加载采集细则；核对报告截图与 Case 描述时直接读取[一致性检查](#case-与截图一致性检查)，不要求重走采集流程或初始化 manifest。报告后置，修改前状态、瞬时错误和短暂过程必须在消失前按需保存。

## 设计原则

证据服务于 Claim（可验收的用户结果），不是为了填满目录。AI 先判断当前 Claim 需要什么证据，再调用浏览器或脚本采集；脚本只负责确定的截图、录制、脱敏和文件写入，不能决定业务是否通过。

同一 session 的证据共享当前已确认的 worktree、开发服务、浏览器 page/context、账号和环境摘要。每条证据至少说明：对什么页面或对象做了什么、看到了什么、结论是什么。截图在改变待验状态前由 AI 目视检查，录屏结束后及时查看关键过程，避免交付时才发现现场已丢失；无法稳定说明 Claim 时标明证据缺口。

需要保护的内容应避开或脱敏后重新检查；无法安全处理时不纳入交付。不上传宿主桌面画面。

## 证据档位

AI 按已确认标准选择最低充分档位，并可在发现争议或差异时升级。档位是采集建议，不是持久化状态；用户明确排除媒体时遵从，不为补档位追问或采集，但不得声称已验证未覆盖的视觉内容。

| 档位 | 默认产物 | 适用情形 | 通过依据 |
|---|---|---|---|
| 轻量 | case 摘要、输入条件、关键观察、结论、已有 runId/可确认代码版本 | 非视觉的普通只读结果，或用户明确不需媒体 | 观察直接覆盖 Claim；信息不足与未覆盖的视觉内容明确标记 |
| 标准 | 轻量 + 目标区域截图 | 用户可见 UI、交互结果、布局、文案、权限显示 | 截图直接命中 Claim，且来自同一 page/context |
| 对比 | 标准 + before/after 或 comparison 资产 | HMR 后变化、修复前后、布局或文案差异 | 两侧对象、页面、环境和采集目的可对应；差异由 AI 解释 |
| 时间/媒体 | 标准或对比 + 短 GIF/video/audio | loading、动画、拖拽、音频或原生窗口 | 媒体覆盖状态变化，静态截图作为补充 |

涉及业务写入时，摘要必须同时说明写前状态、写后观察、是否约定恢复以及实际结果；未完成回读或约定的恢复时不得声称完整通过。默认保留数据不是恢复失败。

## UI、媒体与前后对比最低合同

视觉证据应使评审者能对应页面/对象、有效条件和结果。先从 Claim 确定必要对象、字段、状态及前后关系，再选择最小充分图集；多对象不能只证明其中一个，前后图需能对应同一对象与观察阶段，不规定固定张数。采集后打开实际图片，检查文字可读、关系完整、遮挡和隐私可接受。只截一个关键词和一个客户名字，即使各自清晰，也不能证明二者来自同一有效搜索结果；截图范围应保留该关系所需的输入、列表及必要页面定位。清空的证据需同时说明空输入与恢复后的结果，不能只写结论。

交付前按[Case 与截图一致性检查](#case-与截图一致性检查)核对**最终采用的图集**。脱敏或裁剪后重新检查对象、字段及跨图关系，保留来源；关系缺失时明确证据缺口。

已检查且仍适用的结果可以作为后续 Case 的前置证据，引用原 Case 和采集事实即可，不重复操作、截图或登记虚假的新时间。原始证据不足与产品不通过分开；缺失现场只能按授权补验相关场景并注明新时间，不能靠裁剪、放大、补文字或报告渲染补造。

浏览器截图必须来自当前 session 的真实 Host 和 page/context。浏览器采集前固定 viewport（默认桌面 `1280x720`，移动验收使用 `390x844`，需求另有指定时以当前需求为准），并在资产 metadata 写入 `viewport`、`width`、`height` 和 `capture_mode`。稳定 UI 截图应包含 Claim 所需对象或文案，避开无关 loading、遮罩、toast、推广及需要保护的内容；若错误提示或 loading 本身就是 Claim，则当场保留，不能先等待它消失。截图标签写清区域、目的和时间，不上传完整桌面截图。

iOS / Android 原生采证按对应平台 reference 绑定真实设备与应用上下文，使用设备帧的实际尺寸；上面的浏览器 viewport 默认值不套用于原生截图。裁剪或脱敏后保留来源及实际范围，尺寸与 capture_mode 按现有报告字段合同填写，不虚构浏览器 Host 或 viewport。

需要覆盖长列表、页面整体布局或滚动后状态时，额外采集 `capture_mode=full_page` 的全页截图；它与固定 viewport 截图属于同一 case 的不同证据，不能用全页截图替代首屏或目标区域截图。采集时保留 `case_id`，已有旧资产缺少归属时明确标记，不能凭空补写。

使用当前已确认的 agent-browser session 时，直接复用原 namespace/session 做确定采集：

```bash
agent-browser --namespace <已有namespace> --session <已有session> set viewport 1280 720
agent-browser --namespace <已有namespace> --session <已有session> screenshot <首屏路径.png>
agent-browser --namespace <已有namespace> --session <已有session> screenshot <全页路径.png> --full
```

登记图片时由报告 API 从文件读取实际宽高，显式提供的尺寸须一致；不能用图片像素尺寸或默认值补写未记录的旧 viewport。`--full` 覆盖文档全高；若业务页用内部滚动或虚拟列表，两张图可能同高，应说明限制，不宣称已覆盖全部列表内容。浏览器控制能力不支持固定视口时，明确记录缺口，不能仅填写 metadata 当作已采集。

录屏只覆盖能改变判断的短窗口，开始前和结束后都要知道要证明的状态。GIF 只用于短时变化，长过程使用 video；audio 只有声音本身是 Claim 时才保留。

前后对比两侧必须绑定同一 case、页面位置、账号和环境目的，并使用同一个 `comparison_id`。保留 before/after 标签、viewport/尺寸和差异说明，以便后续按 case 整理。尺寸不一致时并排展示并注明限制，不自动推断差异原因。HMR 证据分为两类：

- 连续性验证：同一 page/context、登录态和业务位置保持，新文案、样式或明确模块版本信号已出现。
- 业务修复验证：真实 bug 的相关代码已修改，受影响动作和断言在更新后重新执行，业务结果仍然正确。

无真实业务 bug 时不制造业务改动；无关文案变化不能证明业务修复成功。

## Case 与截图一致性检查

本检查判断报告中的截图是否支持对应 Case 的描述和结论。现场采集后检查内容，报告交付前再检查实际呈现的对应关系；仅整理已有报告时也适用，不因此重新执行业务或扩充功能测试范围。

逐个核对当前报告中使用截图举证的 Case，不抽样。读取其目标、输入、实际观察、结论及图片说明，打开最终采用的每张实际图片；先描述画面中可见的事实，再与文字核对。不能只读文件名、图片标签、asset ID 或“已检查”记录，也不能把预期结果抄成画面观察。局部更新时，未变的文字、图片和呈现关系可复用已有逐项核对结果；任一项变化后重检受影响部分。

| checkpoint | 核对标准 |
| --- | --- |
| 对象与场景对应 | 图片中的页面、业务对象和关键标识能对应本 Case；不同对象、平台或场景的截图不能混作同一次操作证据。 |
| 条件有依据 | Case 写出的开关、筛选、容量等关键条件，在图中可见或有明确关联的可信前置证据；画面未展示的条件不能靠图片标题或结果提示反推。 |
| 操作阶段对应 | 文字中的操作前、操作后、失败提示、关闭提示后或刷新后，与图片实际阶段一致；拖拽预览、加载中和旧轮次截图不能冒充本轮最终状态。 |
| 结果与描述相符 | 逐项核对文字声称的数量、位置、数值、文案和状态。图中有残留、重复或相反结果时必须指出，不能只看符合预期的局部。 |
| 结论由证据支持 | 每项依赖截图的断言都有对应画面或必要图组；前后图能识别同一对象和变化。单张结果图不能证明完整过程，提示图只能支持实际显示的提示，不能同时证明配置、回滚或保存成功。 |
| 最终呈现对应 | 报告所在 Case、实际展示图片、图片说明、前后顺序和当前/历史归属一致；原图正确但报告引用、分组或裁剪错误，仍视为未完成本项检查。 |

在现有 Case 的实际观察或图片说明中留下简短可核对的依据：**哪张图 → 哪个可见事实 → 支持哪项描述 → 尚不能证明什么**。证据关联使用现有字段，不新增强制表单或假设渲染器有自动识图能力。例如“图 A 可见容量不足提示；未展示关闭提示后的卡片位置，不能据此确认已回滚”，不能只写“截图正常”。

发现不一致时按原因处理：

- **错图、漏图或呈现错误：** 已有正确证据就修正采用关系、标签或展示，重新核对受影响 Case，无需重跑业务。
- **文字超出证据：** 区分需求预期与实际观察，纠正错误描述并明确尚未证明的断言；不能降低既定验收标准来迁就图片。已有独立可靠观察支持业务结论时保留该结论，另列截图缺口。
- **画面与结论冲突：** 先核对对象、条件和阶段；例如 Case 写“移动成功”，图中同一对象却同时出现在原位置与目标位置，须查明是中间态、错图还是实际异常。未澄清前不得宣称该结论证据充分；原业务结论依赖这张图且无其它可靠观察时，该项按信息不足处理，明确违反预期时按不通过处理。
- **原始证据缺失：** 仅在授权范围补验受影响断言并记录新采集时间。只允许整理报告时保留缺口，不自动访问业务或重造现场。

修正后检查最终报告中的实际图文，不以重新渲染成功作为通过依据。仍有影响约定举证的缺口或冲突时保留草稿并说明交付未完成；文件存在、引用合法和图片可打开都不能代替上述内容判断。
