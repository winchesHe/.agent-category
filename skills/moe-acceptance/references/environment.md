# 环境准备与恢复

当前 Case 或单独准备请求缺少环境、版本、路由、设备/应用或资源归属事实时使用本模块。已有健康现场直接续验；平台和做法已明确时可直接进入对应 reference，不要求先读本文件再读所有平台资料。

## 平台与依赖准备

首次准备，或对应平台事实有缺口、变化或失败信号时，只读取受影响平台的具体做法。只准备环境时不要求先制定业务通过标准，也不自动执行后续业务 Case。

| 平台与触发条件 | 按需入口 |
| --- | --- |
| T2 商家 Web：Host/私有代理、浏览器身份、桥接参数、局部组件或结束清理有缺口 | [t2-web](t2-web.md)：服务、路由、登录与桥接的实际合同 |
| iOS：后台连接/按需展示/Expo 交互、多需求隔离、设备/build/Metro/JS 来源、account/API Grey/location、原生动作、异步采证/日志隐私或资源归属有缺口 | [ios-simulator](ios-simulator.md)：后台设备与应用准备、身份、展示和局部恢复 |
| Android：serial/AVD、设备复用/状态隔离、APK/JS、Metro、身份/API 路由、构建/时钟状态、设备采证或私有数据盘清理有缺口 | [android-emulator](android-emulator.md)：设备与应用复用、按需隔离、身份、局部恢复和资源收尾 |
| T2 OBC：Business/name、Customer、路由、MIS 注入边界或共享 impersonate 的恢复有缺口 | [t2-obc](t2-obc.md)：同一次准备中的浏览器、必要 impersonate、客户登录与恢复 |
| Client Portal / Report Card：Host/API 分流、合法客户上下文、打开次数等附带写入范围、局部故障或自有资源清理有缺口 | [t2-client-portal](t2-client-portal.md)：产品 Vite、私有路由与客户访问上下文 |

需要从已运行的 iOS 开发 App 发 API，且主 JS runtime 连接、产品客户端、有界异步回读或重连方式有缺口时，读取 [ios-runtime-api](ios-runtime-api.md)。已有有效通道直接复用，不因纯 UI 续验加载；请求身份的通用选择见 [data](data.md#复用合适的请求身份)。

## 后端依赖

首次准备、目标版本或后端依赖变化时，确认所需服务版本，复用满足依赖的默认环境或已有 Grey；缺少路由时用 `moe-grey` 在 `ns-testing` 创建本任务独立规则并接入当前 App/Web 或 API 通道，确认实际请求命中目标版本后再执行依赖它的 Case。自建规则按[主文件的并发与资源](../SKILL.md#并发与资源)登记并清理。

## 准备结果与接续

在当前会话保留实际入口、可确认版本、必要路由、设备或浏览器引用、身份准备结果及资源归属，说明当前 Case 所需前置是否满足。只补缺项，不引入全量 preflight、全局 ready 标记或新的准备总控。

前置满足后回到原 Case 执行动作与观察；准备成功不能代替业务验收通过。仍有缺口时带上具体事实进入[问题处理入口](../SKILL.md#验收途中遇到问题)，只恢复受影响部分，保留其它有效结果。推进与结束按[主文件](../SKILL.md#继续暂停与结束)判断；只准备环境的任务完成后，按[并发与资源](../SKILL.md#并发与资源)保留需要交付或接续使用的环境。
