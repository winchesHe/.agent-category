# Case 执行与判断

仅在需要业务执行、证据判断或结束核对细节时读取。已有标准和页面时直接继续，不要求阅读其它参考资料后才能动作。

## 复用标准与直接执行

使用当前可编辑 worktree、已登录 page/context、目标环境及已知数据引用；缺少某项工具参数时只补该项，不建立交接文件或健康检查清单。

先复用当前对话、已确认需求或已有验收说明中的目标范围、可观察预期、必要证据和交付物；信息已足够判断就直接执行，不要求用户重复确认或补齐固定表格。只有会改变对错、风险或交付的缺口才先对齐：AI 结合已有材料提出短标准并集中确认，不自己选择一个预期后立即执行。实现和现场可帮助理解语义，不能仅因代码这样写就认定应当如此。

例如，用户只说“验收搜索”，且上下文没有匹配规则时，先提出本轮范围、预期与采证方式，请其确认；已经约定按姓名搜索、清空恢复当前视图并留 UI 证据时，直接做 C1，不再询问截图尺寸或是否出报告。只准备环境、保存即将消失的现场或整理已有结果不需要先制定业务通过标准；临时现场仅作为观察，不据此补写通过。

在已确认标准内形成最小 Claim 和输入，执行必要动作并复用结果继续。动态 case 可以按发现新增、拆分或合并，但不能降低标准；扩大范围或改变预期时重新对齐。不因为没有现成脚本而停止，也不为一次重复操作写 adapter、runner 或宏。

当前 case 的前置有数据缺口才查询和补准备；字段语义或现状不明时先补查询，不因空态或证据不足直接造数。数据准备不能提前完成 Claim 要验证的 UI 动作，API 回读也不能代替实际消费者的观察；需要准备细节时按需读 [data.md](data.md)。环境异常的下一步选择按[主文件的问题处理入口](../SKILL.md#验收途中遇到问题)，本文件只解释动作与业务结论。

## 观察与结论

客户筛选应记录实际条件、结果是否匹配，按需求验证空结果或清除筛选。列表存在、Host 正确或没有登录跳转都不能单独证明筛选通过。

搜索、清空关键词、清除筛选和重置视图不一定等价；先用当前控件或已知实现确认语义，不用相似按钮替代目标动作。连续搜索与清空时，保留原视图及未改变的条件，在清空前保存搜索结果和独立结论；恢复按无关键词的有效范围判断，不要求原页码、顺序或总数完全复原，也不把输入框为空当作结果已恢复。

声明断言覆盖的可见范围、页或已知对象；匹配字段和规则未知时补最小观察，不凭名称猜语义。一个匹配对象只证明该对象，不能代替声明范围内的结果检查。防抖、取消请求或旧列表仍在时，按最终有效动作的结果有界等待，不以固定睡眠、HTTP 成功或中间态判通过。

每个 case 保留目标、实际输入/步骤、观察、三态结论与限制。通过要覆盖 Claim；断言不符为不通过，缺关键观察或环境阻塞为信息不足。业务差异、操作错误和环境失败分别解释，不让脚本退出码代替判断。后续推进按[继续、暂停与结束](../SKILL.md#继续暂停与结束)处理，不从 Case 三态直接推导任务结束。

空结果本身不能定性：已确定应有数据却稳定为空是不通过，缺语义或加载状态则是信息不足。工具超时而无产品期限通常不足以判失败；已有可靠反例或已证实违反约定期限则不能降为信息不足。失败或中断后可继续安全且独立的 case，但不抹掉原结果。

身份失效后先暂停依赖该身份的断言，按授权局部恢复并确认账号、业务范围和当前动作前置。恢复若清掉了关键词，不能把眼前的无关键词列表当作清空动作通过；先补回该动作需要的搜索条件，再实际清空、观察最终结果并留证。仍有效的已完成 Case 证据直接保留，只重验受影响部分；恢复事实如实记录，不默认要求整组重跑。只有 Claim 明确要求登录态或 HMR 状态无中断保持时，才另外验证完整目标过程；恢复后的成功不能证明此前未中断。

非视觉只读结果保留关键文本或结构化观察；依赖页面状态的 Claim 在改变状态前保存并目视检查目标截图，即使操作只读也不省略。图中应能对应条件、对象和结果：例如搜索输入与匹配列表、清空后的输入与恢复列表；孤立文字不能说明两者关系。C1 的有效结果可复用为 C2 前置证据，不重复截图。整体布局才补全页，时间过程才补短媒体；用户明确排除截图时遵从并说明视觉覆盖边界。没有 before 就明确缺失，不事后重造。详细规格只有当前需要时再查，HTML 不是业务前置。

业务写入要记录写前状态、写后回读、是否约定恢复及实际结果。未获写授权时停止写入，已有只读观察仍可保留。

## 完成与结束

当前 case 的业务观察与必要现场证据保存并检查后进入下一个，不清理 session。收尾时按原标准做一次轻量核对，而非只数已执行 Case：

- 相关观察来自当前 worktree 的最新可确认代码，而非仅正确的 Host。
- 每个结论有具体依据；业务三态、证据是否充分、约定交付物是否完成分别说明，未执行和受阻内容明确标出。业务通过但必要截图缺失时保留业务观察，整体交付仍未完成。
- 代码变更、必要仓库检查、风险及提交/推送授权清楚。
- 中文摘要列出账号/环境/数据前置、观察、实际版本和交付状态，已知 runId 可关联。
- 动作顺序和耗时只引用实际轨迹与计时，明确测量范围；未测不填 0，未调用准备工具不为日志补调，准备耗时不等于业务耗时。
- 没有报告需求时摘要即可；需要集中交付时复用结论和已检查证据。纯渲染失败只修呈现；原始证据缺失则标明缺口，仅在授权范围补验相关 Case，并注明新的采集时间与前置，不把新画面当成旧现场或重跑无关 Case。

完成核对后，按[继续、暂停与结束](../SKILL.md#继续暂停与结束)决定下一步，再按[并发与资源](../SKILL.md#并发与资源)处理应结束或保留的资源。
