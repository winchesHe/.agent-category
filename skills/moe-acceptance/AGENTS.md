# moe-acceptance 编写原则

约束本 Skill、references 和 evals 的编写，不是运行时前置或状态机。

## 核心边界

- 一个 Skill、同一 AI、连续 session；环境准备、验收修复和报告整理是按需能力，不包装成 Flow/Delivery 角色或用户交接。
- 已有标准和上下文无变化就直接动作；缺标准时先用已有材料提出短提案并集中对齐，不新建标准文件前置，不阻塞独立环境准备或报告整理。只有明确变化、闲置或失败信号才检查相关组件，不新增全量 preflight、TTL、ready 状态、session manager 或业务 runner。
- AI 做账号、数据、case、修复范围与结论判断；工具提供事实和确定动作。不猜参数/schema/ID，不让脚本成功代表业务通过。
- case 动态形成，worktree 可编辑；HMR 后复用原 tab、身份和数据，只重验受影响内容。连续性与真实业务修复分开，无真实 bug 不制造修复。
- 默认一个、最多两个浏览器上下文，每 session 内 case 串行，共享编辑和服务重启串行。失败只恢复受影响侧。
- 浏览器默认 headless，用户明确要求才使用 head，不在同一 session 内隐式切换模式。iOS 默认后台 `simctl + Maestro`，按需展示目标窗口时复用健康设备、App 与 Metro，不自动切驱动；窗口不决定并行能力，资源和数据按需隔离，宿主共享输入动作串行。
- 默认保留业务数据；先查后建避免污染。任务结束或取消才按收据清理自有运行资源，复用服务、诊断与正式证据保留；失败留收据，禁止全局关闭或杀进程。
- 不默认生产写入，不执行未授权破坏性操作；区分内部测试业务字段与凭据、真实客户隐私。
- 修改代码先看状态和 diff，保留用户改动，不把验收当提交、合并或 stash 清理授权。

## 文档归属与加载

`SKILL.md` 保留每次适用的最小决策、及时留证、安全和资源边界。简单续跑必须能只依靠主文件与已有上下文完成，不强制加载 reference；已知且仍有效的说明不重读。

新增检查要说明触发条件、能改变的下一步决策、可复用观察和失败后的最小恢复。不能改变决策的检查不进入默认路径。

## 证据与呈现

- 证据服务于 Claim，不追求目录齐全。before、瞬时错误和交互过程在状态变化前按需保存；报告可以后置，不可恢复证据不能补造。
- AI 在改变待验状态前检查必要 UI 证据是否可对应条件、对象与结果，不以图片数量或 metadata 代替目视判断；来源、viewport、尺寸、capture_mode 来自实际事实，UI/媒体按 case_id 归属，前后对比用 comparison_id。
- 一个任务固定一个 `report/index.html`，最多一个 Site，更新复用；不为每 case/HMR 生成新报告或部署。
- 复用 `delivery_artifacts.py` 现有 API，`update` 完整替换摘要。空 Case 或未知结论不填通过，渲染器只呈现 AI 结论。
- 报告轮次只用于内容与证据归属，不是业务状态机。新模型的当前证据必须显式选择；历史快照、未选择资产与当前结论分离。纯文案更新或重新渲染不创建轮次，不借替代证据自动改写 verdict；保留旧格式兼容边界，不从不完整历史猜出轮次和采集时间。
- 业务结果、证据充分性和约定交付物分别判断；证据不足不能宣称整体完成。纯报告/发布失败不重跑业务；缺原始证据只在授权范围补验受影响场景并注明新时间。Site 发布遵循 Sites Skill，只交付已检查、符合目标访问范围的内容。

## 实现与日志的诚实边界

`session_login.py` 是顺序准备桥接，`--force-login` 仍先检查 dev/Whistle/浏览器。局部故障用现有组件能力，不编造 MIS-only/repair 子命令或新的修复总控。

日志按当前 `EventLogger` 实际字段说明；不能把 `parentRunId`、`failedPhase`、`parallelGroup`、细分耗时或摘要汇总等未实现设计写成现有能力，也不要求每个业务动作新增日志。实际 runId、seq、phase/action、status、durationMs 和错误事件用于定位，不变成验收状态机。

禁止无界重试或静默重放全部准备；再次运行需明确原因和预算。当前字段默认值不是已经实施重试的证据。敏感键过滤和截断不保证自由文本或 URL 已脱敏，输出仍需检查。

经验文档直接说明适用条件、操作方式和实际限制；测试经过、次数和结果放在任务记录中。修订以当前产品和工具合同为依据，不机械保留历史条目，也不顺带改变函数、参数、输出及清理语义。

平台经验必须区分首次准备与健康上下文续跑。OBC 新浏览器所需的 impersonate 与客户登录属于同一次环境准备，不拆成用户另行启动的身份阶段；已有有效身份直接复用。用不同起始条件验证实际动作选择，而非只验证首次成功路径；研发交付阶段不转化为运行时门禁。

iOS 的设备/应用、开发服务及必要登录也属于同一次准备；后台路径为默认，保留 `pnpm start → i` 的可视或显式选择入口，健康上下文不重放。区分设备启动、App 运行、目标 JS 连接与窗口展示，不从单设备成功推定多设备或独立驱动进程并行已验证。区分 account、API Grey 与 biz location，启动参数按当前产品合同说明其优先级、持久化及与菜单切换的关系，不把源码锚点、参数存在、驱动 tap 返回或隐藏 reset 当作业务通过。平台指引与真实验收分别记录；不借补原生经验增加 runner、全量 E2E 或必跑切换用例。

## 修改前自检

确认当前改动直接服务需求、引用与实际合同一致、简单续跑和独立采证/报告仍成立。代码能力确有缺口才另行设计确认；不为文档整理制造代码拆分。
