# 飞书输出

## 何时读取

目标是飞书 / Lark 文档、Wiki 或白板时读取。优先使用环境中的 `lark-skills` 执行读取、创建、更新和回读；本文件只规定技术文档的渲染决策。

## 文档拓扑

- 小型主题使用单页文档。
- 大型架构使用一个 Overview Wiki 页 + 若干专题子页；根页提供明确导航和返回路径。
- 用 callout 承载每页的一句话结论，用表格表达责任和状态映射，用插图表达复杂关系，插图形式按下文“插图：PNG 图片或白板”选择。
- 不把 Owner、状态、最后校验日期做成默认页头；只有组织流程确实依赖这些字段时才加入。

## 首稿中的富文本设计

在代表性切片中就确定正文的呈现方式，随后随内容一起扩展，不等全部页面写完才统一装饰。根据读者要做的判断选择原生块：

| 信息用途 | 呈现选择 |
|---|---|
| 页首直接回答问题 | 简短结论 callout |
| 承接前文与本页关注点 | 内容简短时使用双栏导读；长解释保持单栏 |
| 有先后依赖的操作或状态变化 | 有序步骤 |
| 并列规则、条件、责任或状态对照 | 无序列表或表格 |
| 容易误判的关键边界、例外 | 局部提示块，写清适用条件与影响 |
| 验证依据与证明范围 | 提示块或对照表，区分“应检查什么”和“本次已验证什么” |
| 命令、字段、参数、路径 | 行内代码；完整操作示例再用代码块 |
| 分支选择与继续阅读 | 有目的说明的导航链接，短入口可用分栏卡片 |

长段同时包含多个规则时先按语义拆解，再决定块类型。编号会暗示先后顺序，不能把并列限制机械转成步骤。提示块只突出需要注意的结论或边界，不把所有正文都放入卡片。

丰富性服务于阅读，不要求每页有相同数量或种类的块。颜色与图标只辅助识别，文字本身必须说明含义；多栏在实际正文宽度下拥挤时改为单栏，不靠缩小字号维持布局。原生语法与写入方式按当前可用的 `lark-skills` 说明执行。

## 插图：PNG 图片或白板

按图的风格和是否需要在飞书内编辑来选择，不默认使用白板：

| 图的特征 | 选择 | 原因 |
|---|---|---|
| 展示型图，依赖渐变、半透明、玻璃质感、阴影或深色质感（如 `fireworks-tech-graph` Style 5 Glassmorphism、Style 8 Dark Luxury） | PNG 图片 | 白板转换会丢掉这些效果，图稿严重失真 |
| 简单扁平、纯色填充，团队需要在飞书内继续编辑 | 原生白板 | 节点、文字和箭头可编辑，转换损失小 |

### PNG 图片

- 先在本地把 SVG 导出为 2 倍分辨率 PNG，再写入文档；导出方法与中文字体问题见 `fireworks-tech-graph` 的 `references/png-export.md`。
- 写入语法：`<img path="@./diagram.png" caption="图注"/>`，通过 `lark-skills` 的 docs `+update`（`block_replace` 或 `overwrite`）写入。图注写在 `caption`，不在图内重复文档已有的标题。
- 图片不可在飞书内编辑；修改时更新源 SVG 后重新导出并替换，源 SVG 与 PNG 一起保留在可追溯位置。

### 原生白板

- 一张白板只回答一个问题，文档内缩放后仍应能读出标题、节点和主路径。
- 深色图稿使用自包含背景和高对比色，避免依赖透明背景推测当前主题。
- SVG 转白板（`<whiteboard type="svg" path=...>` 或 `whiteboard-cli --to openapi`）的已知限制：
  - `linearGradient` / `radialGradient` 不支持，只保留第一个 stop 的颜色，渐变背景会变成纯色。
  - `fill="rgba(r,g,b,a)"` 的 alpha 会被丢弃，半透明卡片变成不透明色，可能让叠在上面的浅色文字不可见。需要透明度时改写为纯色 `fill` 加单独的 `fill-opacity` 或 `opacity`，这两种写法会保留。
  - filter（阴影、模糊）不保留；`foreignObject`、CSS animation 和外链资源也不要使用。
  - 文字使用原生 `<text>/<tspan>`，颜色写成内联 fill/stroke。marker 箭头可以识别为原生连线。
- 通过 OpenAPI 创建节点时显式设置连续 `z_index`：背景为 0、框架为 1，随后按 SVG painter order 递增。不要依赖节点数组顺序推断图层。

两种形式都先用 `fireworks-tech-graph`（如可用）验证几何、文字溢出、箭头碰撞和构图；写入后以飞书中的实际显示为准，不以源 SVG 的效果为准。

## 发布与验收

1. 在写入前确认目标文档、覆盖范围和用户授权。
2. 更新后回读文档结构；图片确认已插入且图注正确，白板回读节点数量、边界和图层顺序。
3. 白板导出或查询，确认文字、节点、箭头均存在，渐变、透明度等效果没有在转换中丢失。
4. 按 [质量门禁的飞书覆盖要求](quality-gates.md#飞书)，在实际页面检查富文本版式、内嵌缩放、主题可读性和专题导航，记录覆盖范围。

接口成功不等于用户看到了正确内容；没有实际显示验收时，不宣称飞书交付完成。
