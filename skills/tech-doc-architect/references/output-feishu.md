# 飞书输出

## 何时读取

目标是飞书 / Lark 文档、Wiki 或白板时读取。优先使用环境中的 `lark-skills` 执行读取、创建、更新和回读；本文件只规定技术文档的渲染决策。

## 文档拓扑

- 小型主题使用单页文档。
- 大型架构使用一个 Overview Wiki 页 + 若干专题子页；根页提供明确导航和返回路径。
- 用 callout 承载每页的一句话结论，用表格表达责任和状态映射，用 whiteboard 表达复杂关系。
- 不把 Owner、状态、最后校验日期做成默认页头；只有组织流程确实依赖这些字段时才加入。

## 首稿中的富文本设计

在代表性切片中就确定正文的呈现方式，随后随内容一起扩展，不等全部页面写完才统一装饰。根据读者要做的判断选择原生块：

| 信息用途 | 呈现选择 |
|---|---|
| 页首直接回答问题 | 简短结论 callout |
| 承接前文与本页关注点 | 内容简短时使用双栏导读；长解释保持单栏 |
| 有先后依赖的操作或状态变化 | 有序步骤 |
| 并列规则、条件、责任或状态对照 | 无序列表或表格 |
| 容易误判的关键边界、例外 | 局部提示块，写清适用条件与影响 |
| 验证依据与证明范围 | 提示块或对照表，区分“应检查什么”和“本次已验证什么” |
| 命令、字段、参数、路径 | 行内代码；完整操作示例再用代码块 |
| 分支选择与继续阅读 | 有目的说明的导航链接，短入口可用分栏卡片 |

长段同时包含多个规则时先按语义拆解，再决定块类型。编号会暗示先后顺序，不能把并列限制机械转成步骤。提示块只突出需要注意的结论或边界，不把所有正文都放入卡片。

丰富性服务于阅读，不要求每页有相同数量或种类的块。颜色与图标只辅助识别，文字本身必须说明含义；多栏在实际正文宽度下拥挤时改为单栏，不靠缩小字号维持布局。原生语法与写入方式按当前可用的 `lark-skills` 说明执行。

## 白板

- 优先生成可编辑的原生白板节点，而不是把图作为不可编辑截图上传。
- 一张白板只回答一个问题，文档内缩放后仍应能读出标题、节点和主路径。
- 深色图稿使用自包含背景和高对比色，避免依赖透明背景推测当前主题。
- SVG 转原生节点时，使用原生 `<text>/<tspan>`、内联 fill/stroke、显式 polygon 箭头；避免 `foreignObject`、filter、CSS animation、外链资源和依赖 marker 的箭头。
- 通过 OpenAPI 创建节点时显式设置连续 `z_index`：背景为 0、框架为 1，随后按 SVG painter order 递增。不要依赖节点数组顺序推断图层。

如果 `fireworks-tech-graph` 可用，先验证几何、文字溢出、箭头碰撞和构图，再转换为飞书节点。

## 发布与验收

1. 在写入前确认目标文档、覆盖范围和用户授权。
2. 更新后回读文档结构、白板节点数量、边界和图层顺序。
3. 导出或查询白板确认文字、节点、箭头均存在。
4. 按 [质量门禁的飞书覆盖要求](quality-gates.md#飞书)，在实际页面检查富文本版式、内嵌缩放、主题可读性和专题导航，记录覆盖范围。

接口成功不等于用户看到了正确内容；没有实际显示验收时，不宣称飞书交付完成。
