# 技术架构文档质量门禁

在代表性切片完成后执行一次，在全部载体交付前再执行一次。门禁用于发现结构性问题，不用于给文档增加无意义的流程字段。

## 1. 事实门禁

逐条检查会影响架构判断的结论：

| 状态 | 判定 | 写法 |
|---|---|---|
| 已验证 | 有当前代码、schema、测试、配置或运行证据直接支持 | 可写成确定结论，并保留可追溯入口 |
| 推断 | 多个事实支持，但没有直接契约 | 明确写出依据和不确定性 |
| 假设 | 用于推进设计，尚未获得证据 | 不进入正式结论，放入待确认项 |
| 冲突 | 两个权威来源给出不同答案 | 暂停扩写，先确定当前生效来源 |

旧文档、注释和命名可以帮助定位，但不能单独把结论提升为“已验证”。

## 2. 认知门禁

- Overview 是否让读者在不进入代码的情况下回答：系统是什么、边界在哪里、谁拥有核心状态与顺序、关键不变量是什么、深入问题去哪一页？
- 每个专题标题能否改写为一个明确问题？开头是否用一句话回答？
- 是否在同一页面频繁跳跃系统级、组件级和函数级抽象？若是，拆页或把实现细节移到代码入口。
- 是否为了显得完整保留了没有读者问题支撑的章节？若是，删除。
- 从 Overview 沿推荐路线能否逐步理解系统？专题是否说明承接的结论和继续入口，平台分支能否回到共同主线？

## 3. 图文门禁

结合 [技术图设计原则](diagram-design.md) 检查构图、图标和样式选择，再检查图稿与全文的关系：

- 一张图只回答一个问题，主阅读方向稳定，节点命名与正文一致。
- 箭头方向、颜色、实线/虚线和标签都有固定语义；图例只解释真正复用的语义。
- 图表达关系或变化，正文解释原因、约束和例外，表格表达精确映射；三者不互相朗读。
- 复杂图在目标页面实际宽度下仍能读出标题、节点和主路径；必要时拆图，不以缩小字号解决。
- C4、Sequence、State、Pipeline、Deployment、Test Architecture 等图型按阅读问题选择，不因流行或工具能力强行使用。

## 4. 机制闭环门禁

与主题相关时，文档应能回答：

- 正常路径如何开始、变化和结束？
- 状态权威在哪里，谁负责顺序和唯一终态？
- 取消、失败、超时、重启或部分成功时如何表达？
- 哪些不变量在异常路径中仍必须成立？
- 哪些测试、运行记录或观测能够证明这些不变量？

不要求每页都覆盖所有问题，但整套文档不能只描述顺利路径。

## 5. 跨载体语义校验和

多目标输出前冻结以下内容，并在每种载体交付后逐项对照：

1. 一句话系统定义。
2. 系统内外边界与外部依赖。
3. 稳定术语及其定义。
4. 核心所有权与状态权威。
5. 关键不变量。
6. 专题问题与一句话答案。
7. 合法终态、失败分类和恢复语义。
8. 验证证据与代码入口。

布局、链接语法和图稿交付形式可以不同；上述技术结论不得漂移。

## 6. 载体门禁

### 飞书

- **切片检查**：Overview 与代表专题在实际文档中呈现拟复用的富文本块和导航；先检查页首、正文密集处和页尾，再扩展同类页面。
- **全部页面回读**：逐页核对正文、Wiki 层级、链接和嵌入资源。更新时确认有效事实与资源没有遗漏；白板的节点、图层顺序和箭头均存在。
- **按版式覆盖视觉检查**：为每种独特版式选择代表页，覆盖最密表格、最长提示块、多栏导航和复杂白板；在实际正文宽度下检查换行、截断、拥挤、异常留白和内嵌字号。相同版式可以抽查，不能据此声称每页都已目视检查；发现问题后补查受影响的同类页面。
- **主题与阅读路径**：检查可用主题下的对比度，实际走通专题导航与返回路径。暗色、亮色未覆盖的部分如实记录；需要改变用户全局设置时遵守工具授权规则，不擅自切换。
- **记录实际范围**：验收记录标明页面、版式、查看区域、主题及遗留缺口。接口成功、导出成功或浏览器连接恢复都不等于视觉检查通过；连接失败时保留已完成结果与待查范围，导出缓存异常和文档内渲染异常分别判断。

### Obsidian

- Overview 能通过 wikilink 到达每个专题，专题能返回 Overview。
- 嵌入资源存在，文件名和链接稳定，frontmatter 服从 Vault 既有 schema。
- 不依赖未确认安装的插件语法。

### Markdown

- 相对链接和图片路径可解析，不包含本机绝对路径、Obsidian wikilink 或飞书专属结构。
- 仓库现有 Markdown lint / 文档构建通过；至少渲染 Overview 和一个复杂专题。

## 7. 完成判定

只有同时满足以下条件才能宣称完成：

- 当前事实有证据，推断与假设被显式标注。
- 文档拓扑和每页问题边界成立。
- 图、正文、表格和代码入口术语一致。
- 所有链接与资源可解析。
- 每个目标载体都经过对应的实际回读或渲染。
- 多目标版本通过语义校验和对照。
