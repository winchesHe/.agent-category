# 技术图设计原则与样式偏好

在设计、重绘或比较技术图时加载。这里维护文档中的构图判断和用户偏好；具体色板、字体、材质、生成参数与几何预算以当前安装的 `fireworks-tech-graph` 为准，不复制维护第二套渲染规范。

## 1. 先确定读者要看懂什么

动笔前用一句话写出图要回答的问题，再列出必要的参与者、阶段、关系和结果。优先复用已有事实与用户认可的图。

- **总工作流**回答“从哪里开始，怎样推进，何时结束，交付什么”。节点优先使用动作或阶段；不展开全部工具、模块、平台和实现细节。
- **架构图**回答“谁负责什么，边界与依赖在哪里”。使用稳定职责和真实所有权，不把阶段顺序误画成系统依赖。
- **机制专题图**回答具体的顺序、状态、数据流或故障恢复问题。总览省略的细节在对应专题展开，不重新塞回总览。

图显得单调或杂乱时，先检查信息取舍和主次层级。增加颜色、图标或阴影不能修复内容模型；也不要为了视觉丰富性增加没有阅读价值的节点。

## 2. 总工作流的优选构图

适合端到端流程总览时，优先尝试“输入／目标 → 核心工作 → 结果”的构图：输入与输出帮助定位，中间主要面积留给关键动作与判断。阶段数量、阅读方向和分区按真实流程决定，不固定卡片数量或三栏模板。

- **主线先成立**：读者先看到起点、关键推进过程与结果。用位置、留白、大小和适度色彩形成焦点；同类阶段对齐，不让所有区域等大、等重、等饱和。
- **反馈回到真实决策点**：存在“操作 → 观察 → 选择下一步”时，优先把局部反馈放在对应阶段附近；跨阶段回退保留真实跨度，标明条件，避免被误读为无条件循环。
- **支路按条件出现**：准备、补数据、恢复等仅在实际需要时连接对应阶段。标签说明进入与返回条件，不能把按需步骤画成每次必经，也不能把失败直接画成已经修复。
- **细节有去处**：模块名、工具名、命令、错误分类等仅在解释当前关系时保留，其余交给正文、表格或专题。若必要分支仍拥挤，拆出专题图，不靠持续缩小字号解决。

这些构图建议适用于流程总览；C4、部署、状态机和时序图仍使用各自的表达规则。

## 3. 图文丰富性来自有用的视觉层级

| 元素 | 设计方法 | 需要避免的结果 |
|---|---|---|
| 图标 | 按当前绘图工具的图标参考选择成熟、同套的图标库；统一线宽、光学尺寸与圆角，优先表达明确对象，如任务单、操作窗口、结果文件 | 随手拼几何形状，或对所有概念重复使用星星、机器人等泛化符号 |
| 图标与文字 | 图标帮助识别，短标签说明含义；抽象判断没有准确图标时直接使用文字。简洁风格可省略图标 | 为每个节点强塞图标，或移除文字后要求读者猜含义 |
| 色彩 | 用主色建立焦点，有限辅助色区分类别或状态；标签、形状或线型同时说明语义 | 每张卡片使用不同高饱和色、只靠颜色解释状态 |
| 字体与文案 | 阶段名短而明确，说明只补充必要含义；采用可正确渲染中文的字体与回退，确认中英文、数字层级协调 | 重复长句、中文缺字、装饰字体妨碍小字号阅读 |
| 容器与连线 | 分区表达真实分组；先排节点，再为主路径和回路留出走线空间，箭头大小与标签权重受控 | 为装饰添加虚假边界、连线压住文字、多个箭头挤在同一点 |
| 页首与留白 | 文档已有标题和介绍时，嵌图默认去掉重复的大标题、副标题和品牌眉题，把面积留给流程；独立分享图按需保留简短标题 | 图中再次放一大段介绍，或删掉理解阶段与条件所必需的标签 |

## 4. 默认优先样式

当次明确指定的样式或已认可的图稿优先；否则从下表选择适配阅读问题和载体的候选。编号不是优先级，候选集也不是禁用其他样式的白名单。需要候选集之外的风格时，简短说明它更适合当前图型的原因。

| Style | 名称 | 优先适用场景 |
|---|---|---|
| 1 | Flat Icon | 日常文档、总流程和通用架构总览；未指定主题时的稳妥起点 |
| 5 | Glassmorphism | 信息量适中的展示型总览；要确认透明叠层后的文字对比度 |
| 8 | Dark Luxury | 深色技术总览和重点流程；中文字体可读性优先于装饰效果 |
| 10 | Cloud Fabric | 具有区域、网络与工作负载归属事实的部署拓扑 |
| 11 | Event Transit | 具有主题、处理顺序、消费组及分支事实的事件链路 |
| 12 | Ops Pulse | 有观测窗口、指标、状态和 trace 证据的运行与可靠性视图 |

选择后，按 `fireworks-tech-graph` 的 `references/style-diagram-matrix.md` 和所选样式文件核对适用条件，生成与验证沿用该 skill 的当前流程。

**Style 10、11、12 含领域语义。** 缺少相应事实时，默认回到 1、5、8 等通用候选；当次明确指定这些样式时，说明缺口，并按绘图工具的合同处理，不编造区域、Topic、实时状态或指标。

## 5. 对比与迭代

- 已有认可的内容结构时，保留流程与术语。比较样式使用同一内容、拓扑、箭头方向、布局骨架和画布比例，避免把内容变化误认为风格差异。
- 材质、配色、字体与装饰服从各自样式；不要把所有候选做成同一种卡片后只替换颜色，也不要混入另一个样式专属的工程符号。
- 默认直接选适配的优先样式制作。用户要求比较时，再生成有明显差异的候选或其明确指定的全集，不把每次画图都变成十二种样式选择流程。
- 反馈“丑、单调、杂乱”时，先定位问题是内容、构图、图标、样式还原还是缩放显示，再修改对应层；复用已认可的部分。

成图按绘图工具要求检查；嵌入文档后的图文关系、实际宽度和主题检查统一使用 [质量门禁](quality-gates.md)。
