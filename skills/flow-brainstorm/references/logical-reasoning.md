# 逻辑推理与思维质量保障

确保 brainstorming 过程中的思维链条经得起逻辑检验。不是要把自由讨论变成形式逻辑课，而是在关键节点用逻辑工具检查推理质量，避免在有漏洞的基础上继续搭建。

---

## 1. 三种推理模式

思维伙伴需要识别当前对话在使用哪种推理，以及什么时候该切换。

### 演绎（Deductive）— 从一般到特殊

**结构**：前提A + 前提B → 结论必然成立

**特征**：如果前提为真且推理有效，结论**必然**为真。不增加新信息，只揭示前提中隐含的东西。

**用途**：验证已有假设的逻辑一致性、检查推理链是否密封。

**典型场景**：
- "如果所有X都是Y，而这个东西是X，那么它必然是Y"
- 用户说"因为A所以B"时，检查这个"所以"是否成立

**常见谬误**：
- 肯定后件：A→B，B成立，所以A成立（错！可能有其他原因导致B）
- 否定前件：A→B，A不成立，所以B不成立（错！B可能有其他来源）

### 归纳（Inductive）— 从特殊到一般

**结构**：观察1 + 观察2 + ... → 一般性结论（概率性，非必然）

**特征**：结论超出了前提给出的信息，因此永远有被反例推翻的可能。但可以通过样本量和多样性来增强可靠性。

**用途**：从具体经验中提取模式、形成初始假设。

**典型场景**：
- "我试过三次都失败了" → 归纳出"这条路可能走不通"
- "所有我见过的成功产品都有X特征" → 归纳出"X可能是成功要素"

**质量检查**：
- 样本够大吗？（3个例子是很弱的归纳）
- 样本够多样吗？（全是同一类情况？）
- 有没有反例被忽略了？
- 是幸存者偏差吗？（只看到了成功的案例）

### 溯因（Abductive）— 最佳解释推理

**结构**：观察到现象P → 如果假说H为真则P可以被解释 → H是P的一个可能解释

**特征**：不保证正确，但给出"在现有信息下最好的猜测"。是创造力最活跃的推理类型——在信息不完整时拼凑故事。

**用途**：面对理解空白时提出新颖假设、诊断问题根因、在不确定中做出有方向的推进。

**典型场景**：
- "用户流失突然增加" → "可能是因为上周的改版"（溯因）
- "这个技术方案应该能工作但实际上不行" → "可能是因为我们忽略了X因素"

**质量检查**（选择最佳解释的标准）：
- **解释力**：这个假说能解释多少已知现象？
- **简洁性**：在解释力相当时，更简单的假说优先（奥卡姆剃刀）
- **类比支持**：在类似情况下，这类解释成立过吗？
- **可证伪性**：这个假说有没有可能被证伪？如何验证？
- **与已知事实的一致性**：是否和已确认的事实矛盾？

### 三者的协作关系

```
溯因 → 产生假说（"可能是因为X"）
演绎 → 推导预测（"如果X为真，那么我们应该观察到Y"）
归纳 → 积累证据（"我们确实观察到了Y，在5个不同场景下"）
```

在 brainstorming 中，**溯因是最常用的模式**——因为我们在探索、在猜测、在构建解释。但需要用演绎检查逻辑一致性，用归纳评估经验支持的强度。

## 2. 论证结构分析

当用户提出一个观点或方案时，帮助他可视化自己的推理链条。

### 论证的基本组件

```
前提1（事实/假设）
前提2（事实/假设）
    ↓ [推理规则]
中间结论
    ↓ [推理规则]
最终结论
```

### 标注系统

对论证链中的每个节点标注其认知状态：

| 标记 | 含义 | 处理方式 |
|------|------|---------|
| ✓ 已验证 | 通过数据/实测/权威来源确认 | 可以依赖 |
| △ 合理推断 | 从已验证事实经逻辑推导 | 标注推理依据 |
| ? 假设 | 未经验证的信念/经验 | 必须标注，可能需要验证 |
| ✗ 存疑 | 有反面证据或逻辑问题 | 需要重新审视 |

### 实操方式

不需要画完整的论证图——在对话中自然地标注：

"你的推理链条大概是这样的：
1. [✓] 用户反馈了X问题（事实）
2. [?] 你假设原因是Y（待验证）
3. [△] 如果Y是原因，那么做Z应该有效（逻辑推导）
4. [?] Z的实施成本可以接受（未评估）

第2步和第4步是悬挂的假设——要先确认哪一个？"

## 3. 常见逻辑谬误检测

在 brainstorming 中特别容易出现的推理错误。不是要当逻辑警察，而是在关键决策节点帮助用户避免踩坑。

### 因果类谬误

**混淆相关与因果**
- 表现："A和B同时出现，所以A导致了B"
- 检查："有没有第三个变量C同时导致了A和B？时间顺序对吗？有没有反向因果的可能？"

**倒果为因**
- 表现："成功的公司都做了X，所以做X能让我们成功"
- 检查："是做了X导致成功，还是成功了才有资源/动力去做X？"

**单一原因谬误**
- 表现："问题就是因为X"
- 检查："真的只有一个原因吗？有没有多因素共同作用？"

### 推理跳跃类

**滑坡论证**
- 表现："如果我们做了A，那么B会发生，然后C，然后灾难"
- 检查："从A到B的概率是多少？每一步跳跃都成立吗？"

**类比滥用**
- 表现："X领域这样做成功了，所以我们也应该这样做"
- 检查："两个场景的结构真的相似吗？关键差异是什么？"

**以偏概全**
- 表现：从少数案例跳到一般性结论
- 检查："样本量够吗？样本有代表性吗？有没有反例？"

### 框架类谬误

**虚假二分法**
- 表现："要么做A要么做B"
- 检查："真的只有两个选项吗？有没有C？A和B能不能同时部分采用？"

**沉没成本谬误**
- 表现："我们已经投入了这么多，不能放弃"
- 检查："如果从零开始，你还会选这条路吗？过去的投入是否应该影响未来决策？"

**确认偏误**
- 表现：只关注支持自己观点的证据
- 检查："有没有主动寻找反面证据？如果你想证明自己是错的，你会去看什么数据？"

**锚定效应**
- 表现：第一个接触到的信息不成比例地影响后续判断
- 检查："这个数字/框架是我们从哪里得到的？如果初始条件不同，结论会变吗？"

### 使用原则

- **不要每句话都检查逻辑** — 那会杀死对话的流动性
- **在分叉点使用** — 当推理链的下一步会显著影响方向时
- **用提问而非断言** — "这里的因果关系成立吗？" 比 "你犯了因果谬误" 更有建设性
- **标注为观察而非审判** — "我注意到这里有个跳跃——从X到Y之间好像缺了一步？"

## 4. 辩证推进法

Thesis → Antithesis → Synthesis。不是为了争论谁对，而是通过对立面的碰撞上升到更高层次的理解。

### 操作步骤

1. **明确 Thesis**：当前主张/方案/观点是什么？
2. **构建 Antithesis**：如果有人要反对这个主张，最强的反对理由是什么？（Steel-Man 对立面）
3. **寻找 Synthesis**：有没有一个更高层次的理解能同时容纳正题和反题的有效部分？

### 示例

- Thesis："我们应该专注做一个产品做到极致"
- Antithesis："市场变化太快，单一产品风险太高，应该多线并行"
- Synthesis："有一个核心产品作为根基，但在其周围保持2-3个轻量级实验来探索方向"

### 什么时候用辩证法

- 用户对某个方向很笃定但你觉得有盲点
- 两个方案各有道理难以选择
- 讨论陷入"这个好 vs 那个好"的拉锯
- 需要从二选一上升到发现第三选项

## 5. Steel-Manning（钢人论证）

Steel-man 是 Straw-man（稻草人）的反面。不是攻击对手观点的最弱形态，而是主动构建其**最强版本**，然后再评估。

### 为什么在 brainstorming 中重要

- 避免过早否定一个方向——你否定的可能只是它的弱表达，不是它本身
- 迫使更深入理解替代方案的逻辑
- 经常在构建强版本的过程中发现新的洞见

### 操作方式

当用户倾向于否定某个选项时：

"在你否定之前，让我试试构建这个选项的最强版本——
假设有一个很聪明的人选择了这条路，他的理由可能是：
1. ...
2. ...
3. ...
在这个最强版本下，你的反对理由还成立吗？"

### 与 Devil's Advocate 的区别

- Devil's Advocate：攻击你喜欢的选项（找弱点）
- Steel-Man：强化你不喜欢的选项（确认你真的有理由否定它）
- 两者互补：Steel-Man 确保否定是基于最强形态的公平评估

## 6. 条件化思维（"在什么条件下"测试）

把"好不好"的二元判断转化为条件分析。

### 核心句式

- "在什么条件下，这个方案会是最优选择？"
- "这个想法在什么情境下会失败？在什么情境下会成功？"
- "这两个方案的优劣会在什么条件下反转？"

### 为什么有用

1. 避免"绝对好"或"绝对坏"的简单判断
2. 把讨论从"我觉得"推向"依赖于什么"——更容易找到验证路径
3. 经常揭示："原来我们的分歧不在方案本身，而在对条件的判断不同"

### 应用场景

- 两个方案比较时：不问"哪个更好"，问"在什么条件下A胜出？在什么条件下B胜出？"
- 评估风险时：不问"这会不会失败"，问"这在什么条件下会失败？这些条件出现的概率是？"
- 做决策时：不追求"正确答案"，而是明确"我们在赌哪些条件成立"

## 7. 认知状态标注

在对话过程中持续标注断言的确定性等级。

### 三级标注

| 等级 | 信号词 | 含义 |
|------|--------|------|
| **已验证** | "数据显示"/"实测结果"/"根据文档" | 可以直接作为推理基础 |
| **推断** | "由此推导"/"逻辑上应该是"/"基于X可以推出" | 需要说明推理依据 |
| **假设** | "我猜测"/"可能是"/"假设"/"直觉上" | 必须明确标注，不能当作已知 |

### 使用规则

- 不需要对每句话都标注——只在**影响后续推理的关键节点**标注
- 当用户把假设当事实用时，温和地标注出来
- 当一条推理链建立在未验证假设上时，指出这个依赖关系
- "你这个结论依赖于前面的假设X。如果X不成立，结论也不成立——我们要先验证X吗？"
