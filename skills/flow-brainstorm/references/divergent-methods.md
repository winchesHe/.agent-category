# 发散思维方法论

当需要产生新想法、打破思维定势、扩大可能性空间时使用这些方法。

---

## 1. 类比迁移（Analogical Thinking）

### 原理

识别看似无关领域之间的**结构性相似**，将一个"源领域"的解法映射到"目标领域"。源域越远，潜在洞见越新颖——但也越需要严格评估映射是否成立。

MIT Sloan Review 经典案例：大奥蒙德街医院的医生研究 F1 赛车进站团队的编排流程来改进急诊病人交接，结果技术错误减少42%、信息遗漏减少49%。

### 操作步骤

1. **抽象化问题结构**：用不含领域术语的方式描述你的问题。比如"信息过载"的本质是"流入量大于处理能力"
2. **远域搜索**：在完全不同的领域寻找相同结构。"流入>处理"在哪里出现过？交通拥堵、水坝泄洪、客服排队...
3. **提取源域解法**：那个领域怎么解决的？限流、分流、缓冲、优先级队列、批处理...
4. **映射回目标域**：这些解法翻译到你的领域意味着什么？
5. **压力测试**：结构映射真的成立吗？有没有被类比掩盖的关键差异？

### 四个实践习惯

- 消费远离自己行业的知识
- 保持玩耍心态——"有意义的飞跃往往在逻辑结束、游戏开始的地方发生"
- 创造安全的推测空间（明确说"这只是类比，不一定成立"）
- 严格评估类比洞见——不是所有结构相似都意味着解法可迁移

## 2. SCAMPER 方法

对已有想法或系统进行系统性变换来生成新可能性：

| 字母 | 操作 | 核心问题 | 示例 |
|------|------|---------|------|
| **S** | Substitute（替换） | 换掉哪个核心元素？用什么代替？ | 线下培训→异步视频 |
| **C** | Combine（组合） | 哪两个不相关的东西合在一起有化学反应？ | 手机+相机=智能手机 |
| **A** | Adapt（借鉴） | 其他场景怎么解决类似问题？能照搬什么？ | Uber的模式→Uber for X |
| **M** | Modify/Magnify（放大缩小） | 把某个维度推到极端会怎样？ | 一次服务1000人 vs 只服务1人 |
| **P** | Put to other uses（挪用） | 这个东西/能力还能用来做什么？ | Post-it本是失败的胶水 |
| **E** | Eliminate（消除） | 完全去掉某个部分会怎样？什么是非必要的？ | 无服务员餐厅 |
| **R** | Reverse（反转） | 反过来做会怎样？颠倒顺序？ | 先付费再使用→先使用再付费 |

### 使用技巧

- 不需要按顺序走完7个——挑2-3个对当前问题最有启发性的操作
- 对每个操作生成至少3个变体后再判断
- 和用户一起做：你抛出一个SCAMPER变换，用户反应，然后迭代
- 特别有用的场景：优化已有产品/流程，而非从零开始创造

## 3. 强制随机输入（Random Entry / Provocation）

来自 de Bono 的横向思维。当思路完全堵住，正常的联想链都走不通时，引入随机但具体的外部刺激来打破固着。

### 约束注入法

引入一个人工约束，强迫在新的解空间中搜索：

**时间约束**：
- "如果必须在48小时内上线？"
- "如果有一年的准备时间？"

**资源约束**：
- "如果预算是0？"
- "如果只有一个人来做？"
- "如果有无限预算？"

**用户约束**：
- "如果目标用户是5岁小孩？"
- "如果目标用户是技术专家？"
- "如果你的竞争对手也在做这件事？"

**技术约束**：
- "如果不能用任何代码？"
- "如果必须是纯硬件方案？"
- "如果只能用2020年之前的技术？"

### 为什么约束反而有用

基于 145 项实证研究的元分析（HBR, 2019）：

- 约束与创造力呈倒U形关系
- 太少约束→缺乏方向和焦点→创造性产出反而降低
- 适度约束→引导注意力到特定子空间→发现非显而易见的解法
- 太多约束→窒息创造力

约束的两种功能：
1. **引导性（Directive）**：将注意力聚焦到特定方向
2. **限制性（Limiting）**：缩窄路径，迫使在更小空间内创新

### Provocation（PO 操作）

de Bono 的 PO（Provocative Operation）：故意说一句"不正确"或"不可能"的话，然后从这个荒谬的陈述出发寻找有价值的方向。

**格式**："PO: [荒谬陈述]" → "如果这成立，意味着什么？哪些部分可以保留？"

例：
- "PO: 用户自己给自己发邮件" → 启发了邮件回忆功能
- "PO: 汽车方形轮子" → 启发了主动悬挂系统

**使用时机**：正常思路完全走不通时。不要在思路还在流动的时候用——那只会打断。

## 4. 思维帽切换（Six Hats 简化版）

de Bono 六顶思考帽的实用简化。核心价值：**把不同类型的思考分开做**，避免同时批判和创造导致的互相抑制。

| 帽子 | 聚焦 | 核心问题 |
|------|------|---------|
| 🔵 **数据帽** | 已知的事实和数据 | 我们实际知道什么？有哪些数据？什么是已验证的？ |
| 🟢 **创意帽** | 可能性，忘记可行性 | 最酷/最疯狂/最有创意的版本是什么？ |
| 🟡 **乐观帽** | 最好的结果 | 如果一切顺利，这带来什么？有什么隐藏的优势？ |
| ⚫ **悲观帽** | 风险和问题 | 最可能出错的是什么？什么会杀死这个想法？ |

### 使用规则

- **一次只戴一顶帽** — 在创意帽阶段不允许批判，在悲观帽阶段不需要想解法
- **明确切换** — "现在我们换一顶帽子，来看看风险面"
- 不需要每次都用全部帽子——按需选用
- 特别有用的组合：先创意帽（发散）→ 再乐观帽（选出有潜力的）→ 最后悲观帽（压力测试）

## 5. "What If" 爆炸法

从一个核心前提出发，快速生成 12-15 个"如果...会怎样"的变体。目标是覆盖从务实到激进的完整光谱。

### 操作流程

1. 陈述核心前提/当前方案
2. 生成变体，覆盖三个区间：
   - **保守区**（4-5个）：微调现有方案
   - **中间区**（4-5个）：改变某个关键假设
   - **激进区**（4-5个）：完全颠覆前提
3. 有趣的想法通常出现在第 8-15 位——前几个往往是显而易见的

### 关键原则

- 不要在生成阶段评价——先数量后质量
- 第一批想法通常是平庸的，告诉用户跳过它们
- 生成后，让用户标记"让你吃惊的"而非"你觉得最好的"——惊讶往往指向真正的新洞见

## 6. Devil's Advocate Flip（魔鬼代言翻转）

拿出当前最被看好的想法，系统性地攻击它。

### 角色设定

框定为一个"见过这种想法失败100次的怀疑论投资人"。每一个发现的弱点要么：
- 揭示真正的缺陷（需要解决）
- 澄清范围（"这个确实不在我们解决的范围内"）

### 攻击维度

- 技术可行性：这真的能做到吗？
- 用户接受度：谁会用？为什么用？
- 竞争：为什么别人没做/做不了？
- 规模：从10个用户到10万个，什么会崩？
- 时机：为什么是现在？
- 团队：你们有能力做这个吗？

### 重要提醒

这个工具只在想法已经有一定成熟度时使用。过早使用魔鬼代言会杀死还在萌芽阶段的好想法。

## 7. Yes, And 链（即兴演出法）

借鉴即兴表演。规则：每次回应必须接受前一个人说的（"Yes"），然后在此基础上叠加（"And"）。

### 用于 brainstorm 的方式

1. 用户给出一个种子想法
2. AI 接受它并在上面叠加一层
3. 用户反应（接受/修改/换方向）
4. 来回 5-7 轮

### 漂移追踪

每 3-4 轮检查一下"我们离原始问题走了多远？"——适度漂移是好的（可能找到了更好的问题），但如果漂移太远需要标注出来让用户决定是否锚定回来。
