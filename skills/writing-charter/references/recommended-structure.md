# 推荐立项结构

这份结构不是 checklist 的替代品，而是更符合 sponsor 和执行团队阅读顺序的成文方式。

## Charter-only 推荐顺序

1. 项目名称 + `> 项目章程 | Owner / Sponsor` 元信息
2. Business Case：受益人与未满足需求（表格或四行声明）+ Supporting Observations + 为什么现在做
3. SMART Objective（"项目结束时：" + 编号列表格式）
4. High-Level Scope（In 表格 + Out 列表 + Deferred 列表）
5. Stakeholder（Power/Interest 矩阵 + Resources 角色表）
6. 执行计划（Budget 明细表 + Schedule 分阶段表 + Risk Register + Communication Plan）
7. 当前结论 / 待拍板项

## Charter + Solution 推荐顺序

当方案已明确，需要一步到位产出完整立项文档时：

1. 项目名称 + `> 项目章程 | Owner / Sponsor` 元信息
2. 受益人与未满足需求
3. 为什么现在做（Why Now）
4. SMART Objective
5. High-Level Scope（In / Out / Deferred）
6. Stakeholder（Power/Interest + Resources）
7. **Solution**（方案概述 + Dependencies）
8. **执行计划**（Budget + Schedule + Risk Register + Communication Plan）
9. 当前结论 / 待拍板项

> 注意：Solution 插在 Stakeholder 之后、执行计划之前。这让读者先理解"谁参与"，再看"怎么做"，最后看"怎么推进"。

## Full Initiation 追加章节

在 Charter（或 Charter + Solution）基础上继续补：

11. Delivery Plan：Schedule + Milestones + RACI + Dependencies
12. Control：Quality Standard + Change Control
13. Closing：Final Acceptance + Administrative Closure + Lessons Learned
14. KO 会必须确认的事项

## 语言要求

- 少用黑话，优先普通业务语言。
- 优先写短句和判断句，不要一层套一层。
- 如果一个词需要解释，直接解释，不靠语气带过。
- 表格内尽量简洁——表格是用来 scan 的，不是用来读长段落的。
